# Decision log

The brief leaves these questions open. Each is decided once, with the reason, and the code and
tests follow it.

| #   | Question                      | Decision                                                                                                                                                                      | Why                                                                                                                                        |
| --- | ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| D1  | Do students sign in?          | Yes, with Google, same as teachers.                                                                                                                                           | A roster of real identities lets teachers recognise and remove students, and lets a student see their classes on any device.               |
| D2  | How is the role set?          | Chosen once at first sign-in (`422 ROLE_REQUIRED` tells the app to ask). Stored on the user, not editable in the app.                                                         | One role per account keeps every permission check a single comparison.                                                                     |
| D3  | Join code format              | 6 random digits from the CSPRNG (`crypto.randomInt`), leading zeros allowed, shown as `482 913`.                                                                              | Numeric is what the brief asks for; 6 digits is easy to read aloud. Guessing is handled by rate limits and expiry, not length.             |
| D4  | Codes per classroom           | Exactly one live code. Regenerating revokes the old one, and its QR, at once.                                                                                                 | One "stop new joins from that code" action, and an unambiguous screen.                                                                     |
| D5  | Does a code expire?           | Yes, 24 hours after creation (`JOIN_CODE_TTL_HOURS`).                                                                                                                         | A code is for one joining session; a photo of the board is useless the next day.                                                           |
| D6  | What does the QR contain?     | A deep link with the code only: `joinly://join?code=482913`.                                                                                                                  | QR and typed code share one server path, regenerating kills both, and the QR reveals nothing to enumerate.                                 |
| D7  | Brute-force protection        | Per student: 5 failed lookups per 15 minutes, then `429` with `Retry-After`. Per IP: 60 join requests per minute.                                                             | With 1,000 live codes in a 1,000,000 space, an attacker has about a 2% chance per hour per account; expiry and regeneration close the gap. |
| D8  | Confirm before joining?       | Yes. `POST /v1/enrollments/preview` shows class, teacher and student count first.                                                                                             | Prevents joining the wrong class from a typo. Rate-limited like a join.                                                                    |
| D9  | Joining twice                 | Idempotent: `200` with `alreadyMember: true`.                                                                                                                                 | Double taps, retries and re-scans are normal. A composite primary key guarantees it under concurrency.                                     |
| D10 | Can a teacher stop new joins? | Yes, `joiningOpen` per classroom; valid codes then return `409 JOINING_CLOSED`.                                                                                               | Lock a class once everyone is in, without losing the code.                                                                                 |
| D11 | Removing and leaving          | Teacher removes a student; a student leaves. Both delete the enrollment.                                                                                                      | A removed student could rejoin with the same code, so the app offers to regenerate right after removing.                                   |
| D12 | Deleting a classroom          | Hard delete, cascading to codes and enrollments.                                                                                                                              | No recovery need in scope; soft delete would add a filter to every query.                                                                  |
| D13 | Another teacher's classroom   | `404`, not `403`.                                                                                                                                                             | Does not confirm that the id exists.                                                                                                       |
| D14 | What students see             | Class name, description, teacher name and photo, student count. Never classmates' names or emails.                                                                            | Data minimisation.                                                                                                                         |
| D15 | How reviewers sign in         | Real Google sign-in, plus seeded demo accounts behind `DEMO_LOGIN_ENABLED` (off by default).                                                                                  | Shared Google test accounts get stopped by new-device checks. The flag is documented and the route does not exist when it is off.          |
| D16 | Expired vs. invalid codes     | Code history is kept, so an expired code answers `410 JOIN_CODE_EXPIRED` even after it is replaced, while a regenerated-away or unknown code answers `404 JOIN_CODE_INVALID`. | The student gets the right fix ("ask for a new code" vs. "check the code"). Only invalid guesses count toward the limit.                   |
| D17 | Refresh tokens                | Opaque, hashed, rotated on every use, with family revocation on reuse. No grace window.                                                                                       | Detects a stolen token on its first replay. The cost (a dropped refresh response signs the user out) is stated in the README.              |
